# WebGL2 pedestrian pose verification — 2026-10-30

The recorded `GL_INVALID_OPERATION: glDrawElements: Vertex buffer is not big enough for the draw call` was
reproduced in the full scene with `forceWebGL: true`, then reduced to `PersonCrowd(1)`, one `PersonRig`, a camera
and hemisphere light. No city builders, culling, shadows or post-processing were needed.

## Before and after

Temporary instrumentation wrapped WebGL2 draw calls and checked `getError()` before and after each call.
Mesh callbacks associated the failing draw with `PeopleNear`; active attribute inspection distinguished the
geometry from the pose storage:

- `drawElements(TRIANGLES, 10302, UNSIGNED_SHORT, 0)` returned error 1282.
- The geometry had 2189 vertices and a maximum index of 2188. All six geometry attributes had matching capacity.
- The extra `nodeAttribute0` had only 496 bytes (31 vec4 bone/appearance records), with divisor 0. The fallback
  treated it as per-vertex input instead of performing the shader's indexed bone reads.

`attributeArray(...).toReadOnly().setPBO(true)` enables three.js's texture-backed indexed reads on WebGL2.
WebGPU continues using storage buffers. The single-person reproduction then reported zero GL errors.

A second probe rendered two initialized rigs, one in each LOD, before and after moving both rigs following shader
compilation. With only `setPBO(true)`, both images had hash `ffc16fd4`: poses were frozen despite CPU buffer updates.
Invalidating the backend-created `pose.value.pbo` texture in `end()` changed the second image to `a682a59f`, with
7905 changed pixels in the left half and 7099 in the right half, and no GL errors. Both meshes had count 1.
The texture-backed arrays had been padded from 124 to 256 floats during compilation; writes used the current arrays.

This probe verifies rendered pose updates for both LODs. It does not measure gait quality or frame rate.

## Full-scene browser checks

The original failure and minimal probes ran in Chrome. Final full-scene checks ran in Edge with the current
`three@dev` CDN modules, separate origins for forced WebGL2 and default WebGPU, and no production debug globals.
The backend identity was reported after renderer initialization. Temporary draw/console instrumentation recorded:

| Backend | Loop frames | WebGL draw calls through frame 60 | GL errors | Console errors / warnings |
|---|---:|---:|---:|---:|
| WebGLBackend | 60 | 76,154 | 0 | 0 / 0 |
| WebGPUBackend | 60 | Not applicable | Not applicable | 0 / 0 |

Both loading overlays cleared and the full city rendered near Zamek Cesarski. Rendered inspection covered the
player's body and surrounding buildings/streets; WebGPU was also viewed in Midday. The checks did not establish
successful travel between districts, detailed culling correctness, sound quality or comparative performance.
WebGL draw instrumentation adds overhead, so its displayed frame rate is not a performance measurement.

## Regression coverage

`node --test tests/pedestrian-crowd.test.cjs` executes the production `PersonCrowd` class with inert geometry and
shader stubs. The initial PBO requirement failed before the first fix; texture invalidation failed before the
second fix. Coverage includes separate pose slots, near/far selection, capacity, buffer replacement/padding,
repeated uploads, no upload for an empty LOD and the WebGPU path without a PBO texture.

The backend's `attribute.pbo` property is an integration dependency. Future three.js CDN updates need both the
draw-error check and the two-frame movement check; a clean console alone would miss frozen animation.

`node --test tests/` passes 289/289 (33.27 s). Browser instrumentation lived only in a temporary local server and
test page; the application source contains no diagnostic hooks.
