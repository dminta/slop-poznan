# Faster boot, part 12: headless polygon-slot x spans, 32 m curb-edge cells and crosswalk-landing rejection (2026-11-19)

## Result

Against baseline `460b807` (detached base worktree vs `perf-boot-12` worktree, Node v26.13.1, five interleaved
headless world builds on an otherwise idle machine, load average 2.7), median total build time falls
**10,637.2 → 10,245.8 ms (−391.4 ms, −3.68%)** and minimum build time falls **10,606.3 → 10,138.3 ms (−468.0 ms,
−4.41%)**. Every interleaved pair (5/5) is faster on the worktree (**−322.1 to −468.0 ms**); run-to-run spread is
**34.8 ms (0.3%)** base / **179.9 ms (1.8%)** worktree. `streetDetails` drops **3,875.1 → 3,518.1 ms median
(−357.0 ms, −9.2%)**; `signalHeads` drops **2,155.3 → 2,103.7 ms median (−51.6 ms, −2.4%)**; `cityGrid` drops
**1,091.6 → 1,080.2 ms median (−11.4 ms, −1.0%)**; `blocks` moves **+14.7 ms** although the block build was not
touched (noise). Retained `heapUsed` after forced GC increases by **+1.89 MiB** (**639.59 → 641.48 MiB**;
`arrayBuffers` **+1.46 MiB**, the two `Float64Array` spans on the retained `BLOCKS` indexes) while `rss` falls
**1,544.6 → 1,496.7 MiB** because the
32 m curb grid replaces 9.0 M fine-cell offsets. All **24** reconstructed build-output SHA-256 hashes match
identically, no test pins or source-slice markers were changed, and the full suite passes **696 / 696**.

A first 5-pair set was taken earlier the same afternoon while co-tenant Node processes held 100 %+ cores (load
average 21.8): it was also 5/5 faster (**−271.5 to −587.5 ms**, median −433.1 ms) but its spread was 2 %, so the idle
set above is the quoted one.

## Method

- Read `AGENTS.md`, `docs/testing.md`, `docs/backlog.md`, and `docs/observations/perf-boot-11-2026-11-16.md` through
  `perf-boot-9-2026-11-14.md` first; no rejected candidate from those records was retried.
- `tools/bench-boot-headless.mjs` runs the headless world build (`config` → `blocks` → `cityGrid` → `streetDetails` →
  `traffic` → `tramLayout` → `railLayout` → `signalHeads` → `paint` → `tramInfra` → `trams`) using
  `tests/helpers/module.cjs` (`loadModule`) with inert Three.js/TSL stand-ins, seeded `Math.random` (4242), real
  `city-config.js` / `geodata.js` and `SPECIES_CROWN_R`.
- The main checkout was not used as the base: it carried unrelated uncommitted work. The base is a detached
  `git worktree` at `460b807` (`/tmp/boot12/base`), and every pair runs the base first and the candidate second
  (`--root /tmp/boot12/base` for base, the worktree itself for the candidate), five times alternating.
- `node --cpu-prof` (3 runs each, `timeDeltas`-weighted median self ms parsed by an uncommitted scratch script in
  `/tmp/boot12/parse-prof.mjs`) ranked application functions before and after edits.
- Uncommitted scratch instrumentation ran an in-memory copy of `js/` to count calls, cell and item visits and
  rejected candidates. No instrumentation exists in shipped `js/`.
- `/usr/bin/time -p` user+sys CPU time was recorded next to each wall run; the candidate is lower in 4 of 5 pairs
  (median **15.65 → 15.28 s**), consistent with the wall result.

## Caller counts and profile findings

Fresh counts from the 2026-11-19 headless build:

- `pointInPolyIndexed` (`city-config.js`): **13,688,150** calls reached the z slot. A per-slot x span (the min/max x
  of the edges filed in that slot) rejected **4,079,071** of them (**29.8%**) without entering the edge loop. The boot
  builds **7,725** polygon indexes and **237,654** slots (3.8 MB of `Float64` spans); the 91,142 slots on the 2,030
  `BLOCKS` polygons account for the 1.46 MiB retained `arrayBuffers` delta.
- `nearestCurbFrame` (`street-details.js`): **22,257** calls. The 4 m curb grid made them visit **3,195,595** rings,
  **18,101,225** cells and only **85,828** edges: 99.5% of the visited cells were empty, because the query point can
  stand ~50 m inside a large block. `blockCurbDist` makes a further **24,777** reach queries over the same grid.
- `clearOfCrosswalks` (`street-details.js`): **159,925** calls testing **1,757,671** landings. A precomputed
  Chebyshev box around each landing rejected **1,697,498** tests (**96.6%**) before the two dot products.
- `clearStreetTree` (`street-details.js`): **84,014** calls, of which 51,388 visit a tree keepout and **510,595**
  keepout items in total; each item recomputed its chord and length.
- `createFootprintIndex` (`road-network.js`): **2,569,988** calls scanning 4.9 M bucket items (2.34 M single-cell
  calls, 231 k multi-cell calls). A per-bucket union bbox rejected 1.29 M single and 304 k multi bucket visits, but
  see the rejected attempts below.
- `curvePoint` (`road-network.js`): **982,597** calls taking **8,334,603** linear table steps (8.5 on average) for
  the 17-point arc-length table.

## Changes retained

1. **Per-slot x spans in `createPolygonIndex` / `pointInPolyIndexed` (`js/city-config.js`).**
   - `createPolygonIndex` records `sx0`/`sx1` `Float64Array`s: the x range of the edges filed in each 4 m z slot.
     A ray crossing can only flip `inside` at an x between an edge's endpoints, so `pointInPolyIndexed` returns
     `false` when `x < sx0[s] - 1e-9 || x > sx1[s] + 1e-9` (the same 1e-9 slack as the polygon bound). Empty slots
     keep `Infinity`/`-Infinity` and reject immediately. This is one test per query, not the rejected per-edge
     x-range branch. `pointInPolyIndexed` self time **276.2 → 219.2 ms (−20.6%)**.
2. **32 m cells in the street-details curb edge grid (`js/street-details.js`, `curbEdgeIndex`).**
   - The grid was 4 m (`nearestCurbFrame` needs a cell containing the query). A measured sweep of the query counts
     with the same searches: 4 m **18.10 M cells / 86 k edges**, 8 m **4.99 M / 106 k**, 16 m **1.53 M / 147 k**,
     32 m **0.57 M / 235 k**, 64 m **0.27 M / 436 k**. 32 m keeps the empty-cell visits down without multiplying the
     exact distance checks; `blockCurbDist`'s 24.8 k reach queries still scan 1-4 cells and 57 k edges. The built
     grids shrink from **9.0 M to 0.14 M cells** (about 36 MB of offsets to 0.6 MB). `nearestCurbFrame` self time
     **267.1 → 30.0 ms (−88.8%)**. The ring break `(ring - 1) * cell > best` remains a conservative lower bound for
     any cell size, and `tests/boot-indexes.test.cjs` compares every frame and reach answer with a plain scan.
3. **Chebyshev footprint reject per crosswalk landing (`js/street-details.js`, `clearOfCrosswalks`).**
   - Each landing caches its rotated-rectangle centre (`_cx`, `_cz`, the point `mid` along its arm) and the
     triangle-inequality radius `CROSSWALK / 2 + max(left, right) + 2.6`. A query farther than that radius plus `2r`
     on either axis cannot pass the exact along/side test. `clearOfCrosswalks` self time **111.4 → 44.4 ms
     (−60.1%)**; `clearStreetTree` (which calls it per candidate) **153.7 → 105.5 ms (−31.4%)**.
4. **Precomputed keepout chords (`js/street-details.js`, `fileTreeKeepout` / `clearStreetTree`).**
   - `fileTreeKeepout` stores `_dx`, `_dz`, `_len` and `_pad = (|dx| + |dz|) / len` once; the 510,595 visits no
     longer recompute the chord and `Math.hypot` per item. The per-item arithmetic (`along`, `side`, `pad`) and its
     rounding are unchanged.

## Rejected attempts (ablated and reverted)

1. **Per-bucket union bbox (`ubnd`) in `createFootprintIndex` (`js/road-network.js`).** It cut the item checks from
   4.9 M to 1.9 M (1.29 M single-cell queries and 304 k multi-cell bucket visits rejected), but a clean 5-pair
   ablation with the same tree showed **0/5 pairs faster** (median **+68 ms**, range 0 to +165 ms) and cost
   **+1.6 MiB**; reverted.
2. **Lower-bound binary search in `curvePoint` (`js/road-network.js`).** 982,597 calls / 8.33 M linear table steps
   looked worth it, but the 3-run sampled profile stayed neutral (136.3 → 136.5 ms) and the extra branches were
   reverted; `pointInPolyIndexed` and the curb grid carried the pass instead.
