# Faster boot, part 5: reuse park lots and trim signal-placement work (2026-11-12)

## Result

Against pristine `de70d64`, median precompile `[init]` falls **6.634 → 6.288 s at 1× (−5.2%)** and
**43.043 → 40.778 s at 6× (−5.3%)**. CityGrid falls 1.484 → 1.265 s / 9.394 → 8.093 s; traffic including
signal placement falls 1.550 → 1.434 s / 10.403 → 9.542 s. These are three paired runs per configuration.
The final implementation changes 16 source lines across three modules, adds no retained index and preserves every
reconstructed build-output hash. No work moves past the first frame.

Total `[init]` through GPU completion falls 8.207 → 7.630 s at 1× and 52.831 → 52.040 s at 6×. The latter is
only −1.5% because median compile time rose 7.682 → 9.045 s on unchanged shaders. This is a synthetic CPU throttle
on a desktop Mac, not a phone result.

## Method

- Read the four earlier boot records and the relevant testing, world, actor and rendering documentation. Their
  scratch harnesses were absent; this pass rebuilt them under `.agent-task/perf`. `git archive HEAD` was extracted
  into `.agent-task/base` before source edits. No other checkout was used.
- Chrome 157, Apple M5 Pro, headless WebGPU, 1280 × 720, DPR 1, `--enable-unsafe-webgpu`,
  `--enable-precise-memory-info`, `--js-flags=--expose-gc`; separate `/private/tmp/boot5-chrome` profile and CDP
  port 9395. The unchanged production entry loads with `?quality=high&stats=1`. CPU throttling is set before
  navigation. A 200 µs CDP profile runs from navigation to the actual `[init]` console event; forced GC then records
  `usedSize + backingStorageSize`. The main precompile result excludes `compile`, `warmup`, `firstFrame`, `gpu`.
  Module evaluation (including the land raster) is outside `[init]`, inside the navigation profile and `loadMs`.
- Profile first: three original baseline runs each at 1×, 6× and in Node, plus a separate instrumented caller-count
  build. The original browser files are `initial-base-*.json`. After isolated change checkpoints, repeat three
  baseline/current pairs at each throttle (`base-{1,6}-{1,2,3}.json`, `final-…`). Those final pairs, without
  simultaneous Node builds, supply all browser medians below. The early exploratory runs sometimes overlapped Node
  work and choose candidates only; they are not the final effect estimate. Neither batch is randomized.
- `node.mjs` uses the test `loadModule` VM loader and inert Three.js/TSL stand-ins, seeded with 4242. It builds
  blocks → cityGrid → streetDetails → traffic → tram/rail layouts → runtime signal heads/lazy links → paint →
  infrastructure → tram graph. Grid live exports and actual species crown radii are passed explicitly. Building
  footprints are included in park cutting; building, landmark and bridge colliders are omitted from downstream
  placement, matching the part-4 reduced fixture. Hashes are outside phase timers except capturing tree sites and
  paint arrays. Three final interleaved Node pairs are `paired-base-node*.json` / `final-node*.json`; the first pair
  also has default 1 ms Node CPU profiles. Node is not a rendering or browser-performance substitute.
- Instrumented copies count calls at each source call site. Seed 4242 and dt=0 make the first-frame actor queries
  deterministic; counters are snapshotted at `[init]`. `base-count-fixed.json` and `final-count-fixed.json` are the
  reported caller counts, not performance measurements. Ordinary-timestep counts were collected too; they vary
  slightly with actor queries before GPU completion. Production has no instrumentation, hooks or globals added.
- `aggregate.mjs`, `median-profile.mjs`, `profile-phases.mjs` and `write-record.py` reproduce the tables. Raw profiles,
  counters, manifests, full test output and browser artifacts remain under `.agent-task/perf` (not added to git).

## Changes retained

1. **Reuse a partial-park block's lot layout across rings (`city-grid.js`).** The build called `blockLots` 935
   times for 246 blocks; one block repeated it 46 times. The lazy `bLots` variable now belongs to the block loop,
   rather than the ring loop. It is first populated at the same tree-layout stage, reused read-only by `distToLots`,
   and dropped at the next block. This removes 689 duplicate builds and 1,120,855 park-polygon queries.
2. **Reject distant segments before projection (`pedestrian-routes.js`, `segmentsNear`).** Signal placement still
   visits candidate edges and crosswalks in the original order, but rejects a segment's AABB grown by the query
   radius plus 0.1 µm before its original projection and `hypot`. Exact projections fall **2,453,400 → 4,573**.
   There is no new index, changed distance formula, altered lazy-link materialisation or retained storage.
3. **Numeric keys in the signal-placement grid (`street-details.js`).** Its curve, lane, crossing, building and
   overhead buckets use `ix * 100000 + iz` instead of allocating coordinate strings. City cell coordinates have
   magnitude below 1,000, so the encoding is collision-free over this world. Filing loops, bucket order and exact
   placement checks remain unchanged. These maps already expire when the audit returns. Despite its name, the
   audit called with `place=true` constructs actual poles/arms/heads: it was inspected and kept, not removed as a
   logging-only pass.

Each row is one browser run at 1× and 6×, then one Node build. These locate the affected phase; repeated paired
medians above carry the final result. Changes were applied and measured one at a time. Rejected trials were removed

| + lot reuse | 6,511 / 40,938 | 15,345 | cityGrid: 1,280 / 7,989 |
| Road-clearance reject (rejected) | 6,438 / 40,583 | 15,224 | blocks: 1,197 / 7,757 |

- **Road-clearance segment box pre-test:** used `best + half + 0.1 µm` as a conservative reach before the
  unchanged signed projection distance. All 60 hashes and over 100,000 exact reference comparisons matched. But
  blocks moved 1,141 → 1,197 ms at 1× and 7,291 → 7,757 ms at 6×; roadClearance self rose about 261 → 274 ms in
  the exploratory 1× profiles. Added comparisons cost more than the avoided hypots here. Removed, including its
  trial-only test; `city-config.js` is unchanged.
- **Fused chunk writing/bounds:** accumulated the original ordered sphere and box unions while copying each chunk's
  matrices, then supplied the local box to `prepareChunkBounds` to avoid rereading matrices. A real pinned-Three.js
  scratch check compared 10,000 rotated/scaled instances in 312 chunks: matrices, spheres, local and world boxes
  were bit-identical, and scene-culling tests passed. Culling still took 456 / 2,813 ms versus 448 / 2,874 in the
  original baseline medians (roughly +2% / −2%, within noise). Reading matrices was not the dominant cost; the box
  corner transforms and shadow triangle bake remained. Removed; `scene-culling.js` is byte-identical to baseline.
- **Per-lane centre rail cache:** a call-local `Uint8Array` avoided asking the identical centre samples on both
  sides. Plain-reference and operation-count tests passed (804 → 603 calls on a clear 100 m track) and all 60
  hashes matched. Traffic moved 1,395 → 1,364 ms / 8,969 → 8,647 ms, while unrelated cityGrid also fell
  1,245 → 1,233 / 7,997 → 7,655 ms. That does not distinguish a small cache gain from drift. Removed, including
  its trial-only tests. The final lane check and clearance functions are unchanged.
- No whole logging-only pass with a material cost was found. Signal-head placement and lazy-route discovery are live
  outputs. No hypot/sqrt substitution, coordinate quantization, polygon arithmetic rewrite, geodata edit, shader
  change, worker, deferral or three.js SHA bump was applied.

## Remaining work and out-of-scope options

The final three named clearance helpers still cost about **5.32 s self at 6×** (2.412 + 1.704 + 1.207).
Even deleting all of them would leave roughly **35.5 s** of precompile init. The dominant retained phases are
traffic including signals **9.54 s**, streetDetails **9.21 s**, cityGrid **8.09 s**, blocks **7.14 s**, and culling
**2.87 s**. In cityGrid, `distToLots` alone is now ~0.77 s self; in traffic, polygon/block queries, corner/lane
checks and tram/rail nearest work remain larger than the trimmed bucket filing.

- **Workers / deferred construction:** cityGrid + traffic offer a 17.64 s phase budget at 6×, an upper bound rather
  than a promised saving. A worker would need pure layout/typed-array outputs for park surfaces/lots/trees or the
  route/signal layout, serialized read-only geometry/collision inputs, and main-thread creation of Three.js objects.
  Deferral would have to split static surfaces from props and signal/route discovery while keeping the loading
  barrier for anything needed by collision, actor spawning and the first visible frame. This pass moves none of it.
- **Culling off-thread:** the 2.87 s phase includes about 1.1 s sampled inclusive in shadow triangle baking. Moving
  that part requires transferring source position/index/matrix buffers and returning per-cell typed arrays; it
  cannot remove main-thread mesh/material setup. Simply fusing the existing matrix passes was measured and rejected.
- **Geodata/prebaked layout:** the unchanged config/module navigation work is outside `[init]`; moving immutable
  layout/triangulation into generated data might address part of the 8.09 s grid phase, but requires a separately
  versioned format and shipping/parse/heap measurements. It cannot be treated as an index-only change here.

Further work should start with a real phone report. For an exact-code follow-up, investigate the remaining callers
of block/polygon queries and the threshold-only `distToLots` consumers before adding a citywide cache. The failed
road pre-test and neutral rail cache are evidence that fewer arithmetic operations do not guarantee a browser win.
