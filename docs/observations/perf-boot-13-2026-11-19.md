# Faster boot, part 13: flat CSR lane-segment grid, lazy curve curvature/tangents, cutSlab/clipHalfPlane, roadway candidate filtering and tree/corner pre-rejects (2026-11-19)

## Result

Against baseline `f4b38aa` (detached base worktree `/tmp/boot13/base` vs working tree, Node v26.13.1, five interleaved
headless world builds, load average 3.91), median total build time falls **10,345.9 → 9,679.8 ms (−666.1 ms, −6.44%)**
and minimum build time falls **10,252.3 → 9,587.7 ms (−664.7 ms, −6.48%)**. Every interleaved pair (5/5) is faster on
the candidate (**−555.8 to −765.0 ms**); run-to-run spread is **139.3 ms (1.3%)** base / **121.5 ms (1.3%)** candidate.
`streetDetails` drops **3,515.5 → 3,265.6 ms median (−249.9 ms, −7.1%)**; `signalHeads` drops **2,120.1 → 1,905.7 ms
median (−214.4 ms, −10.1%)**; `cityGrid` drops **1,134.0 → 1,003.2 ms median (−130.8 ms, −11.5%)**; `blocks` drops
**1,488.9 → 1,439.2 ms median (−49.7 ms, −3.3%)**; `traffic` drops **277.5 → 260.5 ms median (−17.0 ms, −6.1%)**.
Retained `heapUsed` after forced GC falls by **−97.21 MiB** (**641.60 → 544.38 MiB**) and `rss` falls by **−272.37 MiB**
(**1,535.60 → 1,263.23 MiB**; `arrayBuffers` **+27.49 MiB**, `external` **+46.49 MiB**) because `flatSegmentGrid`
replaces 382,900 retained JS segment objects and ~300 k cell arrays across `tramLayout.laneDist` and
`railLayout.laneDist` with two compact CSR typed-array grids. All **24** reconstructed build-output SHA-256 hashes
match identically, no test pins or source-slice markers were changed, and the full suite passes **697 / 697**.

## Method

- Read `AGENTS.md`, `docs/testing.md`, `docs/backlog.md`, and `docs/observations/perf-boot-12-2026-11-19.md` through
  `perf-boot-7-2026-11-14.md` first; no rejected candidate from those records was retried.
- `tools/bench-boot-headless.mjs` runs the headless world build (`config` → `blocks` → `cityGrid` → `streetDetails` →
  `traffic` → `tramLayout` → `railLayout` → `signalHeads` → `paint` → `tramInfra` → `trams`) using
  `tests/helpers/module.cjs` (`loadModule`) with inert Three.js/TSL stand-ins, seeded `Math.random` (4242), real
  `city-config.js` / `geodata.js` and `SPECIES_CROWN_R`.
- The base is a detached `git worktree` at `f4b38aa` (`/tmp/boot13/base`), and every pair runs the base first and the
  candidate second (`--root /tmp/boot13/base` for base, the working tree for candidate), five times alternating.
- `node --cpu-prof` (3 runs each, `timeDeltas`-weighted median self ms parsed by a scratch script in
  `/tmp/boot13/parse-prof.mjs`) ranked application functions before and after edits.
- Uncommitted scratch instrumentation (`/tmp/boot13/diag.mjs`) ran an in-memory copy of `js/` to count calls,
  loop iterations and skip rates before edits. No instrumentation exists in shipped `js/`.

## Changes retained

1. **Compact CSR typed-array `flatSegmentGrid` for `laneDistance` + `segmentGrid` / `tramGrid` cleanups (`js/tram-infra.js`).**
   - `laneDistance` only calls `add`, `within` and `nearestDist` without `data`, `accept` or `crossing`. Replacing
     `segmentGrid(32, true)` with `flatSegmentGrid(32)` packs segment endpoints and bboxes into separate `Float64Array`s,
     builds a CSR bucket table over a flat `Int32Array` cell grid on first query (`compile()`), checks bbox before
     stamp/endpoint projection and splits endpoint-clamped `dot <= 0` / `dot >= l2` cases in `within`. This retains
     **97.21 MiB less `heapUsed`** (and **272.37 MiB less `rss`**) across the two `laneDist` closures while cutting
     `tram-infra` `add` **171.9 → 66.6 ms** and `within` **344.0 → 184.5 + 106.3 ms**.
   - In `segmentGrid.within` (kept intact for `boot-indexes` tests), moves the bbox check before `sg._q` deduplication
     so the 80% of segments failing the bbox test avoid writing `_q`, and hoists the `accept` branch out of the inner loop.
   - Switches `tramGrid` (`layoutRailInfrastructure`) to walked filing `segmentGrid(24, true)` (`tramGrid.crossing` only
     checks `.length`, so insertion order is unused).

2. **Skip unused curvature and tangents in `makeCurve` / `curvePoint` + pre-scaled `ids` in `createFootprintIndex` (`js/road-network.js`, `js/tram-infra.js`, `js/street-details.js`, `js/traffic.js`).**
   - `makeCurve(e, i, f, j, needCurv = true)` skips derivative/curvature work when `needCurv = false` (`pathClear`,
     `inTheWay`); `pathClear` also reuses one point object. `makeCurve` self time drops **220.3 → 129.8 ms (−41.1%)**.
   - `curvePoint(c, s, out, needTangent = true)` shares the Bernstein weights `b0..b3` across `x`/`z` and skips
     tangent/`Math.hypot` when `needTangent = false` (`pathClear`, `configureCompoundCrossings`, `laneDistance`,
     `auditRuntimeSignalHeads`, `boxSamples`). `curvePoint` self time drops **143.4 → 95.7 ms (−33.3%)**.
   - `createFootprintIndex` pre-scales `ids` entries by `4` at build time and multiplies by `0.03125` (`1 / 32`) on query
     (`438.1 → 417.4 ms`).

3. **Flat `GUIDE_FLAT` grid and split first-segment path in `roadClearance`, pre-padded `sx0`/`sx1` in `pointInPolyIndexed`, typed-array `fill`, and bbox-first `isBlockAt` (`js/city-config.js`).**
   - `GUIDE_FLAT` indexes the `32 m` `LANE_GUIDE` cells in a flat array over the road network's cell bounds;
     `roadClearance` handles `list[0]` separately and computes `b = best + half` once per remaining segment (`194.3 →
     144.9 ms`, **−25.4%**).
   - `createPolygonIndex` bakes `±1e-9` slack into `sx0`/`sx1`, and `pointInPolyIndexed` uses `* 0.25` without the `s < 0`
     branch.
   - `fill` in the land-raster IIFE clamps rows to `[index.z0, index.z1]`, reads `index.px`/`index.pz` typed arrays
     instead of `ring[i]` objects, and fast-paths 2-crossing rows without `.sort(...)`.
   - `isBlockAt(x, z, block)` returns `blockAt(x, z) === null` when `!block` and checks `block`'s AABB before
     `inTramSurfaceCut(x, z)` when `block` is given (an earlier draft inverted `!block` and failed
     `tests/tram-surface-height.test.cjs`; fixed and re-verified).

4. **One-pass `clipHalfPlane`, cached piece bboxes in `cutSlab`, and detail-box fast grid for `railWithin` (`js/city-grid.js`).**
   - `clipHalfPlane` removes its per-call closure `f` and evaluates the half-plane value once per vertex instead of twice.
   - `cutSlab` maintains `[minX, maxX, minZ, maxZ]` per piece (eliminating ~2.6 M `piece.every` closures) and reuses
     four vertex objects for the corridor `quad`. `cutSlab` drops **136.3 ms → below top 40 (< 61 ms)**; `cityGrid`
     drops **130.8 ms (−11.5%)**.
   - `railFastGrid()` caches a detail-box flat array of existing `railCells()` bucket lists (`[-10240, 5152) × [-4096,
     4128) m` at 32 m cells) with `Map` fallback outside, leaving `railCells()` intact for `boot-indexes-3.test.cjs`;
     `railWithin` also switches `for..of` to indexed loops and hoists `xLo..zHi` (**259.4 → 224.7 ms**).

5. **Roadway candidate pre-filtering, endpoint block checks, and edge pre-filter in `pedestrian-routes.js` (`js/pedestrian-routes.js`).**
   - `indexStreets()` precomputes `roadwayBounds(e)` once per edge. `roadwayCandidates(a, b)` filters the 64 m cell lists
     against `(a, b)` in `(s, lat)` space so `laneFree` and `wayRuns` short-circuit immediately when no roadway overlaps,
     and single-cell segments test only the filtered list (`onRoadway` drops **135.8 ms → below top 40 (< 61 ms)**).
   - `clear` checks `a`/`b` block membership before `boxWalkable` and tests `block`/`anyBlock` before `walkable(...)` in
     the step loop (`137.9 → 127.7 ms`).
   - `laneClear` checks both offset endpoints against `block` before `boxWalkable`/`segHasRails` and skips any side whose
     endpoints already fail.
   - `cornerClear` pre-filters `block.poly` edges overlapping the `[a, b]` 4 m box when `poly.length > 12`
     (**114.4 → 95.1 ms**).

6. **Typed-array edge cache and single-cell/early-t reject in `outlineRay` (`js/buildings.js`) and AABB/squared-distance pre-reject in `clearStreetTree` (`js/street-details.js`).**
   - `outlineEdgeGrid` caches `eAx, eAz, eDx, eDz` `Float64Array`s (shared with `outlineDistanceTree`), skips `stamp`
     on single-cell queries, and checks `t > 0 && t < best` before dividing for `u` (`blocks` **1,488.9 → 1,439.2 ms**).
   - `fileTreeKeepout` caches `_x0, _x1, _z0, _z1`; `clearStreetTree` unrolls the 4 corner checks, rejects keepouts by
     AABB before division, and filters non-zebra keepouts by squared distance with a `1e-12` ULP guard
     (`clearStreetTree` drops **106.8 ms → below top 40 (< 61 ms)**).
