# Faster boot, part 6: headless polygon, block-query and lot-threshold pass (2026-11-14)

## Result

Against baseline `c363ade` (main checkout vs `agy-boot6` worktree, Node v26.13.0, five interleaved headless world builds), median total build time falls **16,120.9 → 14,717.9 ms (−1,403.0 ms, −8.70%)** and minimum build time falls **15,869.8 → 14,171.7 ms (−1,698.1 ms, −10.70%)**, exceeding the **821.0–875.1 ms (5.1–5.9%)** run-to-run spread. `signalHeads` (which materialises runtime signal heads and lazy pedestrian routes) drops **5,607.0 → 4,153.5 ms median (−25.9%)** / **5,583.4 → 4,001.9 ms min (−28.3%)**; `cityGrid` drops **1,206.1 → 1,097.0 ms median (−9.1%)** / **1,197.7 → 1,059.9 ms min (−11.5%)**. Retained `heapUsed` after forced GC is unchanged (**580.83 → 580.84 MiB**), all **24** reconstructed build-output SHA-256 hashes match identically, and no test pins were changed. Browser boot (1× / 6×) was not run in this pass (left to the coordinator).

## Method

- Read `AGENTS.md`, `docs/testing.md`, `docs/backlog.md`, `docs/observations/perf-boot-5-2026-11-12.md` and `perf-boot-4-2026-11-12.md` first; no rejected candidates from those records were retried.
- `tools/bench-boot-headless.mjs` runs the headless world build (`config` → `blocks` → `cityGrid` → `streetDetails` → `traffic` → `tramLayout` → `railLayout` → `signalHeads` → `paint` → `tramInfra` → `trams`) using `tests/helpers/module.cjs` (`loadModule`) with inert Three.js/TSL stand-ins, seeded `Math.random` (4242), real `city-config.js` / `geodata.js`, and `SPECIES_CROWN_R`. `landmark`, `bridge`, `outskirt`, `airport` and `canopy` builders are omitted, matching the prior headless fixture.
- `node --cpu-prof` (3 runs each, median self / inclusive ms parsed by `.agent-task/perf/parse-cpuprof.mjs`) ranked application functions before and after edits.
- `.agent-task/perf/count-callers.mjs` instrumented a scratch in-memory copy (1% stack sampling, `10×` for `distToLots`) to rank callers of `pointInPolyIndexed`, `blockAt` and `distToLots`. No instrumentation exists in shipped `js/`.
- Five interleaved pairs (`main` then `worktree`, `node --expose-gc tools/bench-boot-headless.mjs --gc`) measured median, min and spread; `.agent-task/perf/compare-interleaved.mjs` aggregates them.

## Caller counts and profile findings

Baseline scratch caller counts:

- `pointInPolyIndexed`: **13,338,449** calls (`10,998,600` from `pointInBlockPoly`, `1,971,100` from `polygonIn`, `242,300` from `pointInPark`, `124,000` from `inPlazaRect`).
- `blockAt`: **4,704,572** calls (`1,275,500` from `laneClear`, `587,600` from `clear`, `427,800` + `322,000` from `splitAlong`, `321,800` + `74,900` from `clearStreetTree`, `199,100` + `190,900` from `failures`, `209,400` from `isOnCurbIsland`). Over half of all `blockAt` calls were `blockAt(x, z) === block` / `!== block` checks where the caller already knew `block`.
- `distToLots`: **67,091** calls (`35,270` + `31,830` sampled from `buildCityGrid`), both threshold-only (`< Math.max(1.2, 6.07 * scale)`).

Why `pointInBlockPoly` ran 11 M times for 4.7 M `blockAt` calls: large blocks early in `BLOCKS` (e.g. `BLOCKS[0]` spanning 2,860 × 1,502 m) appear in hundreds of `BLOCK_GRID` cells, so `blockAt` tested them before reaching the target curb island.

## Changes retained

1. **Threshold-only `lotsWithin(tx, tz, lots, r)` (`js/city-config.js`, `js/city-grid.js`).** `blockLots(b)` precomputes each lot's exact rotated world-axis half-extents (`bx`, `bz`), and `lotsWithin` skips any lot with `|ox| > lot.bx + r + 1e-9 || |oz| > lot.bz + r + 1e-9` and returns `true` on the first lot strictly within `r` m. `distToLots` stays exported.
2. **Same-block predicate `isBlockAt(x, z, block)` + redundant `blockAt` removal (`js/city-config.js`, `js/pedestrian-routes.js`, `js/traffic.js`, `js/street-details.js`, `js/city-grid.js`).**
   - `isBlockAt(x, z, block)` shares `blockCutAt(b, x, z)` with `blockAt`, tests `block` first (bbox, `blockCutAt`, `pointInBlockPoly`), and only scans `BLOCK_GRID` up to `block` when `(x, z)` is inside `block`.
   - `splitAlong` (`pedestrian-routes.js`) drops the redundant `blockAt(p.x, p.z) === block` and endpoint checks inside `push`, since the outer loop already partitioned `[0..steps]` into maximal contiguous `blockAt === block` runs.
   - `createPedestrianRoutes` takes `isBlockAt = null` as an optional 6th parameter (defaulting to `(x, z, b) => blockAt(x, z) === b` so existing unit tests keep their 2–5 argument calls). `nearestCurbFrame` in `street-details.js` keeps `blockAt` so its `boot-indexes.test.cjs` slice needs no context change.
3. **4 m edge-bbox reject in `cornerClear` (`js/pedestrian-routes.js`).** Skips `block.poly` edges whose AABB grown by `4.000001` m excludes `(x, z)` before computing projection and `Math.hypot`.
