# Retained JavaScript heap investigation (2026-11-11)

## Measurement before changes

Baseline is pristine `586fbcc19da61984cf0c25a8a735f1be13204280`. Chrome headless on Apple M5 Pro,
1280 × 720, WebGPU, production modules and a freshly copied `main.js` with scratch-only inspection hooks.
After the loading overlay disappears and 30 frames, stop the animation loop, force GC through CDP and take
`HeapProfiler.takeHeapSnapshot`. No production data was released for these measurements. All sizes below are MiB
(bytes / 1,048,576), called MB in the previous observations.

| Metric | High | Low |
|---|---:|---:|
| `performance.memory.usedJSHeapSize`, forced GC | 995.6 | 921.6 |
| Snapshot total self size, including native nodes | 1009.9 | 939.3 |
| Phase-sampled boot peak | 1279.1 | 1107.6 |
| Time to loading hidden + 30 frames (includes frame wait) | 10.56 s | 11.91 s |
| Scene meshes | 37,826 | 28,366 |

The precise-memory-info flag avoids Chrome's normal bucketed heap readings. Snapshot and performance.memory totals
are different accounting measures and must not be substituted for each other. Peak values are sampled at boot phase
boundaries; they are lower bounds on the instantaneous peak, not a continuous allocator trace.

The comparison Node snapshot calls `buildWorld()` from `tools/bench-world.mjs`, stores its return value, forces GC
and calls `v8.writeHeapSnapshot`. It retains 216.2 MiB in `heapUsed`, 40.3 MiB of ArrayBuffers; total snapshot self
size is 263.8 MiB. Rendering is inert in that harness: it cannot estimate browser geometry/TSL memory. It confirms that
application graphs and spatial indexes are material independently of the renderer.

## Dominators and retainer paths

`.agent-task/analyze-heap.mjs` parses the snapshots incrementally into typed arrays (Chrome's snapshots are ~2 GiB,
32 million nodes, exceeding Node's maximum single-string size). It constructs strong-edge predecessors, computes
reverse postorder and iterates immediate dominators to convergence (35 passes), then sums self sizes up the dominator
tree. Weak edges are excluded; V8's internal ephemeron edges remain as encoded. An internal/shared reference can make
a node a root child, so a small `renderer` retained size does **not** mean its caches cost nothing. Shared buffers
are counted once. Rows on the same ancestor path overlap; do not sum them.

Low has the same 89.52 MiB street context, 41.92 MiB curb index and 39.88 MiB corridor callback. Its scene-exclusive
retention falls to 48.58 MiB. Thus the misplaced build caches affect both tiers, independently of post-processing.

Largest **self-size classes**, not additive retained-root estimates: ArrayBuffer backing stores 393.98 MiB,
boxed numbers 122.88, array elements 111.64, plain Objects 95.83, NodeData 38.69, Array objects 27.85,

bounds and segment endpoints), not in one huge array that can simply be converted to Float32. NodeData represents
440,999 shader compiler cache objects; deleting that renderer-private cache would need a separate lifecycle audit.

## Readers and safe candidates (recorded before implementation)

- **Curb edge cache:** `street-details.js` `curbEdgeIndex`, `blockCurbDist` and `nearestCurbFrame` are used only by
  lamp and mapped-tree placement. Their last consumer is the OSM tree loop. Returned `update` updates signal texels
  and light pools; returned signal-head routines use poles, crossing/landing checks and lane geometry, never these
  curb indexes. Clear this private derived cache after tree construction: estimated 41.9 MiB, low risk.
- **Placed-tree index:** `reserveTree` / `clearOfTrees` run only while keeping/relocating tree sites, ending at the
  procedural-tree relocation loop. `createTreeField` copies the final sites into its own runtime representation.
  The bucket index itself is not a LOD input. Clear the private index: estimated up to 11.9 MiB (shared sites stay).
- **Wall index:** `wallHit` reads `wallGrid` for street-name-plate placement, and its only caller is that placement
  loop. No runtime raycasting uses it. Clear the private index after its last use: estimated 6.5 MiB.
- **Tree lane keep-outs / lot-frame cache:** `clearStreetTree` uses `treeKeepouts` only during tree placement;
  `inLot` uses `lotCache` only when placing kiosks/columns/flower stands. They are derived indexes, not the actual
  network or block lot geometry. Candidate for clearing after placement, subject to measured exclusive size.
- **Rail collision callback:** `controllers.js` invokes injected `keepOut(x,z)` during collision/teleport checks.
  `has` reads only the tile Map and key arithmetic. Moving that reader into a module-level factory that captures
  only `tiles` leaves its arithmetic, Uint8 data, and public API identical, while severing the accidental link to all
  railway construction queries. Estimated saving ~37 MiB: the raster itself must remain. No clearing of the returned
  layout's diagnostic query functions; headless tests/tools may still use those.
- Keep collider objects and spatial lookup, road network/connector caches, pedestrian lazy route inputs, map layers,
  audio signals, tree source matrices and streamed building records. They have real runtime consumers in
  `controllers.js`, `traffic.js`, `pedestrian-routes.js`, `city-map.js`, `audio-system.js`, `trees.js`, and
  `buildings.js`. Precision-changing Float32 conversions are not a behaviour-identical substitute.

These are targeted ownership changes established from retained paths and reader searches, not a repeat of the
rejected `releaseBuildData()` pass. No GEO or BLOCKS field is a release candidate.

## Three.js CPU attribute copies

The pinned commit is `0a980dcf032223a274fcdd60ab56330f1321cca0`. Source inspection uses that exact commit's
`src/renderers/webgpu/utils/WebGPUAttributeUtils.js`,
`src/renderers/webgl-fallback/utils/WebGLAttributeUtils.js`, and the supplied pinned builds.

The high scene's unique attribute backing buffers total about 255 MiB: position 104.44, normal 41.97, uv 26.08,
instanceMatrix 70.99, aTreeData 5.44, plus smaller attributes. All remain reachable after upload. This is one CPU
array per distinct BufferAttribute/backing store, **not** a full vertex-array copy per 37k geometry wrapper:
`scene-culling.js:chunkInstancedMesh` reuses non-instanced attributes and index by identity, copying only instance
attributes/matrices into spatial chunks. `trees.js` similarly shares template vertex/index attributes across cells,
with separate matrices and aTreeData for the independently repacked LOD prefixes. GPU buffers are additional storage.

A general `attribute.onUpload(() => { attribute.array = null; })` is unsupported here:

- WebGPU `createAttribute` reads the array, may convert/pad it, and copies it into mapped GPU storage. It does not call
  `onUploadCallback`. The fallback's `createAttribute` has that callback **commented out**, before it determines the
  array element type and byte length. This is WebGPURenderer's WebGL backend, not legacy WebGLRenderer.
- WebGPU `updateAttribute`, fallback `updateAttribute`, renderer memory accounting and binding construction read CPU
  arrays. `main.js`'s storage-instance swap must happen before first compilation; the arrays cannot be dropped there.
- `InstancedMesh.computeBoundingSphere` and raycast/getMatrixAt in `three.core.js` consume CPU matrices/positions.
  Tree `rebuild` recomputes bounds and writes active prefixes; building, traffic, tram and pedestrian pools also update
  their arrays. Scene chunking and shadow baking read vertices and matrices before rendering. Matrix freezing avoids
  transform recomputation; it does not make these instance buffers dead.
- The app uses explicit colliders, not a production THREE.Raycaster, but this does not remove backend array readers.
  The pinned WebGPU device-loss handler reports loss and stops rendering; it does **not** automatically reconstruct
  the device. Recreating a renderer or reuploading/disposal would need the original arrays. Do not claim seamless
  recovery, or use the lack of recovery as grounds to discard sources.

No CPU attributes will be discarded in this pass. An indexed, losslessly deduplicated geometry representation or a
renderer-supported immutable GPU-only attribute facility could be separate work; neither is a verified drop-in fix.

## Implemented changes and after measurements

Only two production modules changed. `street-details.js` clears six private derived Maps after its tree field has
consumed the final sites: `curbEdgeIndexes`, `placedTreeCells`, `wallGrid`, `treeKeepouts`, `osmCells`, `lotCache`.
The latter two are read only by `nearOsmTree` during procedural-tree placement and `lotsOf` during kiosk/column
placement. The returned signal-head methods and light update keep their required pole, landing, plaza, signal and
source records. `tram-infra.js`'s module-level `createRailCorridorTest(tiles)` makes the same boolean lookup in its own
lexical scope. The final crossing clears still edit that same Map, and layout diagnostic queries remain available.

Relevant production readers: [street placement and cleanup](../../js/street-details.js:1896),
[railway reader factory](../../js/tram-infra.js:86), [teleport exclusion](../../js/controllers.js:517),
[per-frame corridor collision](../../js/controllers.js:1100), [tree LOD repacking](../../js/trees.js:1131).

| Metric (same 1280 × 720 WebGPU boot) | High before → after | Low before → after |
|---|---:|---:|
| Post-GC JS heap, precise memory API | 995.56 → **891.04 MiB** (−104.51) | 921.60 → **818.48 MiB** (−103.11) |
| GPU memory | **390.326 → 390.326 MiB** | **223.277 → 223.277 MiB** |
| Phase-sampled peak JS heap | 1279.1 → 1171.9 MiB | 1107.6 → 1293.3 MiB |
| Loading hidden + 30 frames | 10.56 → 14.21 s | 11.91 → 11.35 s |

The high after boot overlapped the full test suite; these timings and peaks do not establish a boot-speed or peak
improvement. Clearing references does not force immediate GC. In particular the low after run deferred collection
through warm-up: the peak got worse despite a smaller live heap. This fix meets the retained-heap target, not a claim
that boot OOM risk has disappeared. About 800–900 MiB still remains, and city-grid construction peaks before either
ownership fix can take effect. GPU memory, scene mesh counts and **every scene attribute byte total** are identical
before/after for each tier (the full `renderer.info.memory` object also compares equal).

The high after snapshot totals **905.54 MiB**, vs 1009.92 before (−104.38). The street context falls
**89.524 → 23.348 MiB** (−66.176). The railway layout context disappears from that callback's retainer path;
its raster is 2.634 MiB, against 39.875 MiB for the old callback's context. This accounts for a further ~37.24 MiB.
Backing-store self size falls 393.98 → 352.70 MiB, boxed numbers 122.88 → 98.34, and array elements
111.64 → 95.31. Shader NodeData stays about 38 MiB. This corroborates the ownership explanation, rather than
inferring it from the overall heap delta.

## Equivalence and browser validation

- `node --test tests/`: **537 pass, 0 fail**, 128.5 s. New focused reader tests check negative/fractional coordinates,
  both sides of 64 m tile boundaries, empty tiles, and crossing clears applied after the callback is created.
  `node --test tests/rail-corridor-reader.test.cjs tests/boot-indexes.test.cjs`: 8 pass.
- Pristine archive: `git archive 586fbcc` extracted to `.agent-task/base/`. The scratch equivalence script runs the
  existing full headless world fixture (landmark/building/bridge colliders, building-cut grid, street furniture and
  trees), the furnished road network, pedestrian routes, and both tram/rail layouts. Cycle-aware hashing preserves
  number values, field order, typed-array types/bytes and graph identity; functions and private query stamps are
  excluded. **All eight SHA-256 hashes match**: colliders, footprints, tree sites, network, fully materialized route
  segments/crosswalks/ways, tram layout, rail layout and the collision raster sampled at every metre across the
  detail box (including negative tile boundaries). This is the fixture's output, not an assertion that inert stubs
  reproduce GPU geometry. The route materialization was slow but completed in both arms; no bounded replacement
  was ultimately needed. Full hashes are in `.agent-task/equivalence.json`.
- `node tools/bench-traffic.mjs --only centrum --seed 4242 --json <output>`: both five-minute outputs are byte-identical,
  SHA-256 `ecfc47d0bd1318a630f41155c8dae22fd4440a9fc35c5443d72a5ece19128eb2`.
- High and low, WebGPU and forced WebGL2: normal boots, walk/drive/fly, teleport to Kaponiera, open/close the full map,
  golden → midnight → golden, mute/unmute. Clean console, no compile warning. The audio context reaches `suspended`
  when muted and `running` on unmute. Screenshots of the normal scene were inspected; headless output cannot verify
  the subjective audible mix.
- Deterministic A/B: freshly copied main, seeded randomness, dt 0, sky speed 0 and rebaked IBL, SSR off, trees/dynamic
  actors hidden, HUD hidden (otherwise its live radar introduces differences). Four fixed views (Rynek, Jeżyce roofs,
  Centrum, Wilda roofs), golden and midnight, both tiers and backends: **all 16 WebGPU pairs are pixel-identical**.
  WebGL2 is **not completely bit-identical**: high has at most 39 changed pixels / max channel delta 10 / maximum mean
  absolute RGB delta 0.0000803 out of 255; low at most 48 pixels / max 1 / mean 0.0000203. Both Rynek views are exact.
  A second pristine WebGL boot is pixel-identical to the first, so the small A/B residual must not be dismissed as
  measured baseline noise. It is confined to distant edges, with no visible object/shadow change; its precise cause
  remains unresolved. This is the one requested visual proof that was not met literally. Individual results are in
  `.agent-task/pixel-diffs.json`.

## Reproduction and remaining limits

Scratch contains `refresh-harness.py`, `perf-harness/heap-run.mjs`, `node-heap.mjs`, `read-snapshot.mjs`,
`analyze-heap.mjs`, `inspect-heap.mjs`, `equivalence.mjs`, `perf-harness/check-browser.mjs`, `pixel-diffs.py`, the
snapshots, JSON reports and screenshots. Serve the worktree on port 8120. For example:

```sh
python3 .agent-task/refresh-harness.py
node .agent-task/perf-harness/heap-run.mjs high after-high
node --expose-gc .agent-task/node-heap.mjs
node --max-old-space-size=8192 .agent-task/analyze-heap.mjs .agent-task/after-high.heapsnapshot
node .agent-task/equivalence.mjs .
node .agent-task/perf-harness/check-browser.mjs smoke-low '' 'quality=low&backend=webgl'
```

The snapshots are large; keep the parser's numeric sections streamed. Dominator subtree totals overlap when a row
is an ancestor of another row, and renderer WeakMap sharing prevents assigning all shared shader/geometry memory to
one convenient scene/renderer root. The scratch inspection hook adds references to already live application roots,
so exclusive retained sizes can differ from an uninstrumented production snapshot.

No GEO/BLOCKS nulling, precision changes, texture downscales, population changes, geometry deletion, CPU-attribute
release, renderer upgrade, chunk/LOD changes or renderer-private cache mutation. No real phone, mobile Safari,
device-loss recovery, sustained roaming/thermal test or audible listening session. A further ≥100 MiB would require
another demonstrated ownership fix or a larger representation change: static scene vertex buffers alone are ~173 MiB,
but unsupported post-upload deletion is not an acceptable way to reclaim them. Shader caches and packed exact
simulation records are future audit candidates, not measured savings promised by this change.

An optional alternating boot-repeat probe captured baseline high at 994.52 MiB / 10.72 s, then timed out
waiting for readiness on the next run. A follow-up retry also timed out waiting for readiness. These repeats
are excluded from before/after claims; the completed original captures and all normal smoke runs remain the
measurement evidence. No boot-speed or peak-memory improvement is established.
