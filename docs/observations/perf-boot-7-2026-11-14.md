# Faster boot, part 7: headless rail-within, wire-support grid, segment-grid and footprint-index pass (2026-11-14)

## Result

Against baseline `5015aa1` (main checkout vs `agy-boot7` worktree, Node v26.13.0, five interleaved headless world builds), median total build time falls **14,914.4 → 13,560.1 ms (−1,354.3 ms, −9.08%)** and minimum build time falls **14,634.5 → 13,452.4 ms (−1,182.1 ms, −8.08%)**, exceeding the **563.0 ms (3.8%)** main / **339.7 ms (2.5%)** worktree run-to-run spread. `signalHeads` (runtime signal heads and lazy pedestrian routes) drops **4,207.5 → 3,092.2 ms median (−1,115.3 ms, −26.5%)**; `streetDetails` drops **4,493.8 → 4,357.6 ms median (−136.2 ms)**; `railLayout` drops **1,093.8 → 1,054.1 ms median (−39.6 ms)**; `paint` drops **90.2 → 79.6 ms median (−10.6 ms)**. Retained `heapUsed` after forced GC is unchanged (**583.14 → 583.26 MiB**, +0.12 MiB), all **24** reconstructed build-output SHA-256 hashes match identically, and no test pins were changed. Browser boot (1× / 6×) was not run in this pass (left to the coordinator).

## Method

- Read `AGENTS.md`, `docs/testing.md`, `docs/backlog.md`, `docs/observations/perf-boot-6-2026-11-14.md`, `perf-boot-5-2026-11-12.md` and `perf-boot-4-2026-11-12.md` first; no rejected candidates from those records were retried.
- `tools/bench-boot-headless.mjs` runs the headless world build (`config` → `blocks` → `cityGrid` → `streetDetails` → `traffic` → `tramLayout` → `railLayout` → `signalHeads` → `paint` → `tramInfra` → `trams`) using `tests/helpers/module.cjs` (`loadModule`) with inert Three.js/TSL stand-ins, seeded `Math.random` (4242), real `city-config.js` / `geodata.js` and `SPECIES_CROWN_R`.
- `node --cpu-prof` (3 runs each, median self / inclusive ms parsed by an uncommitted scratch script) ranked application functions before and after edits.
- An uncommitted scratch script instrumented a scratch in-memory copy (sampling `pointInPolyIndexed` 1/100, `railClearance` 1/20, `nearest` 1/10, `outlineDist` 1/10, `createFootprintIndex` 1/50; exact counts for `wireSupportClear`). No instrumentation exists in shipped `js/`.
- Five interleaved pairs (`main` then `worktree`, `node --expose-gc tools/bench-boot-headless.mjs --gc`) measured median, min and spread.

## Changes retained

1. **Reuse `supportCells` in `wireSupportClear` (`js/street-details.js`).** Iterates only the `supportCell` (8 m) grid cells overlapped by `[min(from.x, to.x) - 0.3, max(from.x, to.x) + 0.3] x [min(from.z, to.z) - 0.3, max(from.z, to.z) + 0.3]` instead of scanning all `supports`. Zero new storage.
2. **Threshold-only `railWithin` + `railBoxHasSegs` (`js/city-grid.js`, `js/pedestrian-routes.js`, `js/road-paint.js`).**
   - `railWithin(x, z, d)` uses squared distance with a `±1e-12` relative ULP guard and `Math.hypot` boundary fallback for exact bit-identity, returning `true` on the first segment `< d` and skipping empty `Map` cells without allocating `[]`. Attached as `railClearance.within`; `clearOfRails`, `pedestrian-routes.js` (`wayClear`, `laneClear`, `landing`, `roomToWait`, `clearHazards`) and `road-paint.js` (`layoutBusMarkings`, `onTrack`) use it with fallback to `railClearance`.
   - `railBoxHasSegs` (`railClearance.boxHasRails`) checks once per `laneClear` track whether any rail segment AABB overlaps the track's `[minX, maxX] x [minZ, maxZ]` padded by `LANE_INSET + RAIL_KEEP`, skipping per-step rail checks on clear tracks.
3. **Allocation-free `nearestDist`, `within` and deferred result in `segmentGrid` (`js/tram-infra.js`).**
   - `nearest` avoids `|| []` on empty cells, pre-rejects with `d2 > bestD2 * (1 + 1e-12)` before `Math.hypot`, and allocates `{ seg, d, t, qx, qz }` once at return.
   - Added `nearestDist` (returns scalar distance) for `laneDistance`, `trackDist`, `railDist`, `tramDist` and `within` (early-exit boolean) for `supported` / `levelGrid` threshold checks.
   - `roadDist` returns `g` immediately when `roadClearance(x, z) <= -1.75` and clamps `laneDist` search radius to `Math.min(RAIL_ROAD_KEEP + 3, g + 1.75)`.
4. **Filter-first and hoisted bounds in `createFootprintIndex` (`js/road-network.js`).** Checks `(flags[id] & mask)` before loading `bounds[o..o+3]`, hoists `ix0..iz1`, row key, and `starts[bucket + 1]`.

## Rejected attempts

1. **`laneGrid = segmentGrid(12, true)` (`js/tram-infra.js`).** Shrinking `laneGrid` cells from 32 m to 12 m caused `r = 6.5` queries to span 4 cells instead of 1–2, increasing `Map.get` lookups: `nearestDist` self rose **810.1 → 955.2 ms** and `add` rose **165.7 → 238.7 ms** (total profile median **15,128.8 → 15,560.1 ms**). Reverted to `segmentGrid(32, true)`.
2. **Flat `Int32Array` cell grids for `railWithin` (`js/city-grid.js`) and `createFootprintIndex` (`js/road-network.js`).** Replacing `Map.get` with `Int32Array` over the bounding box regressed both in Node `cpu-prof`: `createFootprintIndex` self rose **590.6 → 1,019.1 ms** and `railWithin` self rose **642.4 → 715.2 ms** (total profile median **15,128.8 → 15,920.3 ms**) due to cache misses and bounds clamping across sparse queries. Reverted both.
