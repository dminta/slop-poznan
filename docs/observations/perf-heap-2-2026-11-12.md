# Retained JavaScript heap, second pass (2026-11-12)

## Method

Baseline is `ae1116c` in the `cx-perf-heap-2` worktree. Chrome 157.0.8103.79 headless, Apple M5 Pro,
1280 × 720, WebGPU, pinned three.js `0a980dcf032223a274fcdd60ab56330f1321cca0`, HTTP port **8132**.
All sizes are MiB (bytes / 1,048,576). The backlog historically calls these MB.

A scratch copy of `main.js` imports the production modules and exposes already-live roots for inspection. It also
records `performance.memory.usedJSHeapSize` at each `[init]` boundary. After the loading overlay hides and at least
30 frames, stop the animation loop, call CDP `HeapProfiler.collectGarbage`, read the precise memory API and take
`HeapProfiler.takeHeapSnapshot`. The peak is the largest phase sample, a lower bound on the instantaneous peak.
The snapshot includes native nodes; its total self size is a separate accounting measure from the memory API.
`--enable-precise-memory-info` avoids bucketed readings. No production inspection hooks were added.

The streaming parser handles ~1.7–1.8 GiB snapshots without constructing one enormous JS string. It stores nodes,
edges and strong predecessors in typed arrays, excludes weak edges, traverses reverse postorder and iterates immediate
dominators to convergence (35 passes), then sums self sizes up the dominator tree. V8's encoded ephemeron edges
remain included. Shared buffers count once. Rows on an ancestor path overlap; **do not add the table's rows**.
Renderer WeakMaps and shared shader graphs can put memory under GC roots rather than a convenient application owner.

Each repeat uses a new page target and closes the preceding one. A discarded early low run reused the high page's
renderer process/context and read 1,703 MiB; it is excluded. HTTP caching is explicitly disabled for final captures:
one intermediate low capture still used the old street-details module (791.23 MiB versus the corrected 783.25 MiB
before the final paint-map release), so that capture is excluded too. Snapshot analysis and tests overlapped some
per-change boots; the separate three-run timing comparison is the regression check, not those single-run timings.

## Ranked candidates and changes

1. **Building staging, ~20 MiB, low risk.** The `buildCityBlocks` shared closure retained `buckets` (10.096 MiB)
   and `roofs` (9.741 high / 9.699 low). Facade boxes have already been copied into instance attributes when the
   bucket loop ends. `roofs.finish()` similarly completes the static roof instances. Runtime detail and lighting
   read `allBlocks`, their pools and the quadtree, never either builder. Empty the private buckets and drop the roof
   builder reference immediately after `finish()`. The roof scene objects stay alive through the scene until culling;
   culling's replacement chunks keep their required attributes. No attribute is nulled or disposed.
2. **Footprint indexes, ~8–9 MiB, moderate risk covered by exact tests.** The network's curb Map retained 9.944 MiB
   and its obstacle hash 7.494 MiB. Replace the bucket arrays/object graph with exact Float64 bounds, Uint8 predicate
   flags, a numeric cell-to-bucket Map, and Uint32 CSR offsets/rectangle ids. The two finished query closures retain
   **5.095 + 4.126 MiB**, down from 17.438 MiB. Keep the 16 m cell arithmetic, insertion order and strict overlap
   inequalities. The flags encode the existing pedestrian blocker and small/non-outline road blocker predicates.
   No Float32 rounding, per-query object, callback, array or iterator is introduced. Input footprints are immutable;
   player collision query stamps and later tree colliders are separate from these network inputs.
3. **Remaining local construction owners, ~15 MiB, low risk.** Drop street-details' temporary `treePositions` list
   after `createTreeField` copies it into LOD arrays (3.467 MiB), and its local references to the three tree-pit meshes
   after adding them to the scene (4.528 MiB of obsolete original mesh retention after chunking). Preserve the LOD
   buffers, actual sites needed elsewhere, colliders and every scene chunk. Clear road-network's `keptEdge`, `inOf`,
   `streetTracks` and `paintNodes` after the last lane/paint update. Their readers only deduplicate edges, test
   build-time tram conflicts and map original nodes to paint nodes. Returned `paintEdges`, graph nodes, connectors,
   lazy pedestrian queries and the signal audit remain available. The paint Map's exclusive retention rose to
   4.757 MiB after the other construction maps were cleared, exposing additional dead graph records; it was measured
   before clearing it as well.

These are local ownership changes and one immutable query representation. No GEO/BLOCKS nulling, geodata rebuild,
renderer upgrade, private cache deletion, post-upload attribute release, LOD/population/distance change or texture
change. Legacy persistence keys remain untouched.

## Investigated and left unchanged

- **Raw geodata:** live GEO object retains about 5.501 MiB; its module/source/bytecode retains 15.197 MiB, including
  8.679 MiB source text. These are distinct. The previous nulling experiment saved only ~20 MiB overall and was
  rejected by the user for risking late readers. This pass confirms those owners but does not repeat that approach.
  Rails, map layers, lazy routes and block lot inputs still have consumers. No format change is justified here.
- **Land rasters and guide/map indexes:** `LAND_CODE` and `LAND_DIST` each retain 18.421 MiB; they drive runtime land,
  shore-margin and teleport queries. `GUIDE_GRID` is 8.120 MiB, `ROAD_GRID` 3.183 MiB, the controller collider index
  3.405 MiB, route wall cells 4.599 MiB and way lookup 3.882 MiB. Their late/runtime readers rule out clearing them.
  Packing additional indexes is possible future work; it was not implemented or assigned a speculative saving.
- **Shader NodeData/cache:** baseline high has **437,594 NodeData objects / 38.394 MiB self size**, low 38.126 MiB;
  96 named WGSLNodeBuilder nodes and 280 named NodeCache nodes were found (name-based counts include metadata).
  A sampled retained path is `ShaderNodeInternal.jsFunc → closure context.builder → WGSLNodeBuilder → cache /
  globalCache → NodeCache.nodesData → per-stage NodeData`. The pinned build's `NodeBuilder.getDataFromNode` creates
  and reads those per-stage entries; NodeCache is a WeakMap with optional parent fallback. Separately,
  `NodeManager.getForRender` caches NodeBuilderState by render cache key, increments `usedTimes`, and its normal
  render-object deletion decrements that count before removing an unused state. `_createNodeBuilderState` carries
  shader strings, bindings, attributes, observer, transforms and runtime update-node lists. `dispose()` is the full
  renderer teardown boundary. A completed compile is therefore not a demonstrated teardown boundary for all those
  graphs or future material/environment/camera recompilation. Clearing private caches would bypass ownership and
  may provoke rebuilds or lose required state. **No cache mutation was tried; measured saving applied: 0 MiB.**
- **Geometry CPU arrays:** still required by this pinned renderer (see the previous heap record). No on-upload release
  was attempted. Tree instance pools and source matrices remain needed for runtime LOD repacking.

## Reproduction and limits

Scratch under `.agent-task/` contains the pristine `git archive HEAD` baseline, `refresh.py`, `cdp.mjs`, `run.mjs`,
`repeats.mjs`, `shots.mjs`, `smoke.mjs`, `analyze.mjs`, `inspect.mjs`, the streaming snapshot parser's binary arrays,
JSON measurements, screenshots and test logs. Nothing in that directory is added to git. Example commands:

```sh
python3 -m http.server 8132
python3 .agent-task/refresh.py
node .agent-task/run.mjs low done-low yes
node --max-old-space-size=8192 .agent-task/analyze.mjs .agent-task/done-low.heapsnapshot
node .agent-task/repeats.mjs perf-final perf
```

Use headless Chrome on CDP port 9332 with `--enable-unsafe-webgpu --enable-precise-memory-info --js-flags=--expose-gc`
and a separate temporary profile. Performance repeats wait another eight seconds for the `?stats=1` five-second
window before stopping and collecting. Screenshot copies seed Math.random, freeze simulation dt, stop cloud drift,
reapply the lighting/IBL preset, hide trees/dynamic actors and the HUD, and draw four frames from each fixed camera.
They test static scene equivalence while the normal unmodified-timestep smoke runs exercise actors and tree LOD.

No real phone, 4 GB device, Safari, subjective audible listening, device-loss recovery or thermal endurance test.
Measurements are headless desktop WebGPU results. Lower retained memory alone does not prove a lower instantaneous
allocation peak or solve low-memory loading failures. The still-large scene/geometry, runtime indexes and shader
graphs are the remaining owners; further changes need a new measured representation/lifecycle argument.
