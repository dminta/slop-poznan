# Faster boot, part 9: headless caller bbox/early-exit, rail-within single-cell, cut-check split and signal-bucket pass (2026-11-14)

## Result

Against baseline `d498a2e` (main checkout vs `agy-boot9` worktree, Node v26.13.1, five interleaved headless world builds), median total build time falls **12,045.0 → 11,620.7 ms (−424.3 ms, −3.52%)** and minimum build time falls **11,847.8 → 11,499.0 ms (−348.8 ms, −2.94%)**. Every interleaved pair (5/5) is faster on the worktree (**−227.0 to −675.8 ms**); run-to-run spread is **1,351.5 ms (11.2%)** main / **1,024.5 ms (8.8%)** worktree (driven by cold-start Run 1; Runs 2–5 spread is **268.8 ms / 2.2%** main, **198.2 ms / 1.7%** worktree). `signalHeads` drops **2,499.8 → 2,203.9 ms median (−296.0 ms, −11.8%)**; `cityGrid` drops **1,313.9 → 1,221.3 ms median (−92.6 ms, −7.0%)**; `streetDetails` drops **4,183.2 → 4,139.6 ms median (−43.6 ms, −1.0%)**; `traffic` drops **289.7 → 268.2 ms median (−21.5 ms, −7.4%)**. Retained `heapUsed` after forced GC increases by **+0.53 MiB** (**585.18 → 585.71 MiB**, from `x0`/`x1` polygon-index bounds and `ex`/`ez`/`L2` on 6,059 `railCells` segments), all **24** reconstructed build-output SHA-256 hashes match identically, and no test pins were changed. Browser boot (1× / 6×) was not run in this pass (left to the coordinator).

## Method

- Read `AGENTS.md`, `docs/testing.md`, `docs/backlog.md`, `docs/observations/perf-boot-8-2026-11-14.md`, `perf-boot-7-2026-11-14.md`, `perf-boot-6-2026-11-14.md`, `perf-boot-5-2026-11-12.md` and `perf-boot-4-2026-11-12.md` first; no rejected candidates from those records were retried.
- `tools/bench-boot-headless.mjs` runs the headless world build (`config` → `blocks` → `cityGrid` → `streetDetails` → `traffic` → `tramLayout` → `railLayout` → `signalHeads` → `paint` → `tramInfra` → `trams`) using `tests/helpers/module.cjs` (`loadModule`) with inert Three.js/TSL stand-ins, seeded `Math.random` (4242), real `city-config.js` / `geodata.js` and `SPECIES_CROWN_R`.
- `node --cpu-prof` (3 runs each, `timeDeltas`-weighted median self / inclusive ms parsed by an uncommitted scratch script) ranked application functions before and after edits.
- an uncommitted scratch script instrumented a scratch in-memory copy (exact totals and last-call repeats, 1/50–1/100 stack sampling) to rank call sites of `pointInPolyIndexed`, `pointInBlockPoly`, `blockAt`, `isBlockAt`, `roadClearance`, `railWithin`, `createFootprintIndex` and `tram-infra` `within`. No instrumentation exists in shipped `js/`.
- Five interleaved pairs (`main` then `worktree`, `node --expose-gc tools/bench-boot-headless.mjs --gc`) measured median, min, spread and retained `heapUsed`.

- `tram-infra` `within`: **1,341,493** calls (**531,900** `laneDist.within`, **399,050** `tramWithin`, **254,350** `trackWithin`, **139,600** `railWithin`).

## Changes retained

1. **Polygon `x0`/`x1` bounds, inlined `polygonSlot`, and `blockOwnCutAt` split (`js/city-config.js`).**
   - `createPolygonIndex(poly)` records `x0, x1` alongside `z0, z1`; `pointInPolyIndexed` rejects `x < index.x0 || x > index.x1 + 1e-9` and inlines `polygonSlot` (`Math.floor((z - index.z0) * 0.25)`).
   - Split `blockOwnCutAt(b, x, z)` (`b.roadCut` / `b.tramCut`) out of `blockCutAt`; `blockAt` and `isBlockAt` already check `inTramSurfaceCut(x, z)` at entry, so their loops only call `blockOwnCutAt` when `(b.roadCut || b.tramCut)` is truthy.
2. **Single-cell fast path and precomputed segment vectors in `railWithin` + early-exit partial-park vertex check (`js/city-grid.js`).**
   - `railCells()` precomputes `ex, ez, L2` on each of the 6,059 `GEO.rail` segments.
   - `railWithin` hoists `ix0..iz1`, fast-paths `ix0 === ix1 && iz0 === iz1` without the nested loop, and reads `s.ex, s.ez, s.L2`.
   - Partial-park ring containment check replaces `ring.filter((p) => pointInBlockPoly(b, p.x, p.z)).length` with an early-exit loop that stops once `inside + (ring.length - i) < need` (`need = ring.length * 0.8`).
3. **Single-cell fast path in `createFootprintIndex` (`js/road-network.js`).**
   - Fast-paths `ix0 === ix1 && iz0 === iz1` with a single `cells.get(...)` lookup instead of the nested `ix`/`iz` loop.
4. **Empty-cell skip, lazy fallback and single-lookup bucket filing (`js/street-details.js`).**
   - `clearOfCrosswalks` skips empty `landingGrid` cells (`if (!list) continue;`) instead of allocating `[]`, and hoists `row = ix * 100000`.
   - `nearestCurbFrame` defers allocating its fallback object until `bestI < 0`.
   - `auditRuntimeSignalHeads`'s `file` helper hoists `ix0..iz1` and uses one `map.get(k)` lookup when the bucket already exists (preserving the exact `ix * 100000 + iz` expression for `boot-indexes-5.test.cjs`).
